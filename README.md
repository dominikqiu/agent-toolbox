# Agent Toolbox

让自然语言需求更清楚，让 agent 更高效地交付可用成果。

Agent Toolbox 收集和开发用于提升 prompt 质量、组织 agent 执行、验证交付物的小工具。希望用户可以用简短、自然的方式表达需求，由工具帮助 agent 理清目标、补齐必要上下文、控制任务范围，并推进到可检查、可使用、可继续维护的结果。

目前从轻量 skills 起步，后续按实际需求加入脚本、模板和评估工具。

## 我们关注什么

一次有效的 agent 工作，应当让需求、执行和交付连起来：

```text
自然语言请求 → 明确目标与约束 → 执行任务 → 验证产物 → 交付或交接
```

| 方向 | 希望解决的问题 |
| --- | --- |
| Prompt 质量 | 从简短请求中明确目标、必要上下文、范围和完成标准，减少歧义与无关信息 |
| 执行效率 | 减少重复澄清、无效计划和上下文消耗，让 agent 持续推进任务 |
| 可交付物 | 明确输出位置、格式和验收依据，让结果能被使用、审查和复现 |
| 工作连续性 | 在长任务、中断或更换 agent 时，保留足够精简的状态以便继续 |

这里的交付物可以是通过相关检查的代码变更、有来源的调研报告、符合要求的文档，也可以是能运行的小工具。不同任务采用相应的验证方式。

## 快速开始：prompt-to-action

这个 skill 适合“知道要什么，但不想每次填写一份完整需求模板”的工作方式。默认不展示改写后的 prompt，不要求用户确认流程；简单任务直接完成，复杂任务才保存简短交接。

### 1. 获取工具

```sh
git clone https://github.com/dominikqiu/agent-toolbox.git
```

### 2. 安装到工作项目

把 `skills/prompt-to-action` 文件夹复制到目标 agent 支持的 skill 目录。对于支持项目级 `.agents/skills` 的 Codex 工作区，结构为：

```text
你的项目/
  .agents/skills/prompt-to-action/
    SKILL.md
    README.md
```

### 3. 设置为默认工作方式

在目标 agent 会加载的持久指令中追加下面这段。例如使用项目级 `AGENTS.md` 时，保留已有规则，只追加配置；路径按实际安装位置调整。

```text
处理我的可执行任务时，默认使用 prompt-to-action skill
（.agents/skills/prompt-to-action/SKILL.md）。
补齐任务目标、范围和完成证据后直接执行，
不要先展示优化后的 prompt 或要求我确认流程。
只有影响结果或授权范围的关键缺口才提问。
```

### 4. 直接描述你的任务

例如：

> 修复这个报错，并验证相关功能。

> 分析这个仓库，给我一份适合当前项目的实现建议。

> 把这些笔记整理成可以发给同事的方案文档。

Agent 应从已有上下文补齐任务定义，再执行和验证；目标仓库、受众或关键约束无法确定且会影响结果时才询问。说“只优化 prompt”或“先给方案，不执行”，即可限定本次任务边界。

安装和自动发现方式依赖宿主。当前提供的是文本 skill，尚未完成不同 agent 产品的兼容性验证；skill 不新增工具权限，也不自动提供后台调度或持久化服务。详见[使用说明](skills/prompt-to-action/README.md)。

## 设计原则

- **交付导向**：从最终产物与完成证据反推任务定义，推进到用户要求的交付边界。
- **低摩擦**：可合理推断的信息无需反复确认；重大歧义与授权缺口仍需澄清。
- **上下文节制**：入口简短、资料按需读取，只保存继续工作所需的事实。
- **按复杂度组织工作**：简单任务直接做，复杂任务才引入计划、状态或协作。
- **保留用户意图**：补齐执行条件，不擅自扩大目标、虚构需求或增加权限。
- **用证据说明完成**：区分实际验证、合理假设和未完成事项，不以“已完成”的文字代替产物。

## 如何判断工具有用

新增工具应给出输入示例、预期产物和适用边界。优先在同类真实任务中比较使用前后的表现：

| 观察项 | 记录方式 |
| --- | --- |
| 用户介入 | 为澄清、纠偏或恢复任务需要多少轮沟通 |
| 交付质量 | 是否满足验收要求，产物是否完整、可用 |
| 执行成本 | 完成时间、上下文或 token 消耗（宿主可提供时） |
| 返工与恢复 | 首次交付需修改多少，中断后能否继续 |

比较时记录模型、环境和任务条件。这些是评估方向，目前尚无量化效果基准，也不承诺固定比例的效率提升。

## 后续探索

以下为候选方向，尚未实现，会根据实际使用反馈调整：

- **Prompt 检查**：定位目标歧义、缺失约束和无关上下文，给出最小修改建议。
- **交付物验收**：将任务要求转换为可执行或可人工检查的验收清单。
- **上下文交接**：生成精简的任务状态，帮助后续 agent 接着工作。
- **效果评估**：用可复现任务比较不同 prompt、skill 和执行策略。

## 增加工具

- skill 放在 `skills/<name>/`，以 `SKILL.md` 为入口，详细用法放独立 README。
- 小脚本可放在 `tools/<name>/`，附运行要求和示例；有实际工具时再创建目录。
- 将新工具加入上方目录。保持入口简短，按需读取资料，避免每次加载全部工具说明。
- 不提交凭据、运行日志或个人任务上下文。

欢迎通过 Issue 描述真实工作中的问题，附上脱敏后的输入、期望产物和当前不足；提交新工具时提供最小使用示例及已知限制。
